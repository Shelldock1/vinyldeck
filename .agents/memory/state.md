## Linux Support (experimental, this checkout)
- Playback authority: `src-tauri/src/media/linux.rs` reads/writes MPRIS (`org.mpris.MediaPlayer2.*`) over the session D-Bus with `zbus` blocking API. Snapshot maps `PlaybackStatus`, `Metadata` (`xesam:title|artist|album`, `mpris:length`, `mpris:artUrl`), `Position`, and `Can*` flags onto the existing `MediaSnapshot`. Artwork resolves `data:`/`file://`/`http(s)` URLs into the same data URL the SMTC path emits.
- `src-tauri/src/media/platform.rs` is the cfg shim: Windows → `smtc`, Linux → `linux`, other targets → SMTC's neutral stubs. Poller/commands call `super::platform::*`, so the frontend command names (`cmd_smtc_*`) are unchanged.
- Window chrome: Linux has no client-side GTK headerbar in tao, and mutter server-side decorations follow the (light) system theme, so `GTK_THEME` cannot restyle them. `decorations` is therefore `false` and `src/components/TitleBar/` supplies the chrome: drag region, minimize/close, plus invisible `ResizeHandles` calling `startResizeDragging`. The bar hides in fullscreen mode.
- `show_main` re-centers after leaving fullscreen because the fullscreen placement otherwise leaves the window partly off-screen.
- Dev-loop deps for this machine live in a user-level sysroot (`~/.local/tauri-sysroot`) wired through `.cargo/config.toml` `[env]`; no root packages were installed.
- Not yet done here: Linux scrobble-free polish, `.desktop`/icon install is user-level only, and `zbus`/`ureq` are Linux-only target dependencies.

### Linux software-render paint path (`src/styles/soft-render.css`)
- Problem: on this machine WebKitGTK 2.52 spawns no GPU process, so the page rasterises and composites on the CPU. The full Noir stack cost 110-190 ms per frame (5-9 fps) and hover paints took 220 ms — the lag was in the page, not in Tauri: the same page in `webkit2gtk-4.1` MiniBrowser burns ~126% CPU while a trivial page there holds 62 fps, and no WebKit env knob (`WEBKIT_FORCE_COMPOSITING_MODE`, `WEBKIT_DISABLE_DMABUF_RENDERER`, `WEBKIT_SKIA_*`, MSAA, `WEBKIT_WEB_RENDER_DEVICE_FILE`, …) changed it.
- Fix: `src/main.tsx` sets `data-soft-render="1"` on `<html>` before first paint when the user agent is Linux (not Android); `src/styles/soft-render.css` then drops the per-frame composites that a CPU compositor cannot keep up with. Windows/macOS keep the full optical stack.
- What the stylesheet removes: `mix-blend-mode` outside the vinyl subtree, all `filter` (incl. the `url(#vinyl-marble-turbulence)` / liquid-glass lens fields), all `backdrop-filter`, every `box-shadow`, the ambient velvet/orbs/swirls/grain layers, the vinyl ghost/glow (both need a blur), and idle keyframe animation. The album-art ambient glow (`.ambient-layer__base::after`) and the ambient base/readability/vignette stay. Glass panels keep their tint but render as a flat fill.
- What stays on the vinyl (2026-10-21 revision): the groove pass keeps its authored `mix-blend-mode` (`--pressing-groove-blend`, default `luminosity`) because without it the rings paint as flat grey bands; everything else still renders unblended. Visible layers: pressing base, pressing depth, sheen, the two counter-reflections, the label stack, the two zero-blur disc edge rings, and one static radial-gradient "shadow" behind the disc (`.vinyl-wrapper::before`) standing in for the blurred drop shadow. Hidden because their paint is not worth it: `vinyl-translucent-ghost` and `vinyl-glow` (filter-dependent), plus `vinyl-pressing-texture` and `vinyl-reflection` (measured ~4 ms/frame together; the sheen already carries the gloss).
- Measured cost of the material pass (release build, 900x737 Glass with art ambient, disc spinning, dev probe removed afterwards): 21.1 fps / 49 ms with every layer, 22.0 fps / 47 ms with the groove blend, 23.8 fps / 43 ms in the shipped set, 29.6 fps / 35 ms for the stripped "aggressive" set. So the shipped look costs ~8 ms/frame over the flat version; do not re-add texture/reflection without re-measuring.
- Measured after (release build, 900x700, glass + Art Ambient): 21-28 ms/frame idle (35-48 fps vs 5-9), 34-40 ms while the disc spins (25-33 fps), `hover_transport_ms` 35-59 ms (was 220), `repaint_ms` 45-53 (was 350), `cmd_smtc_snapshot` 23-32 ms (was 166-198), `cmd_settings_update` 43-49 (was 347-400), `open_settings_ms` ~440-460 (was 665-720). `#root` hidden measures 16 ms, so the remaining gap is the app's own content. After the vinyl restoration: 34 ms/frame with the disc spinning (~29 fps) and 39 ms hover repaint — same band as before, so the material costs no measurable extra.
- Restoring *all* decoration was measured and rejected: full decor keeps ~15 fps and 97-124 ms hover. The disc's blurred shadow alone costs ~14 ms per frame; panel shadows are only expensive once the window repaints as a whole. Hence: blends allowed on the disc only, blur nowhere.
- The measurements above came from a temporary Rust probe (`dev_perf.rs`, env-gated `VINYLDECK_PERF_PROBE`) that was removed after verification; the same approach (`#root` hidden = frame floor, then hide/re-add one layer at a time) reproduces them.
